Webpack Encore est un outil qui simplifie l'utilisation de Webpack dans Symfony. Voici ses principaux avantages :
Gestion des assets modernes :
Compilation de SASS/SCSS en CSS
Minification des fichiers JS et CSS
Support de ES6+ avec Babel
Gestion des modules JavaScript
// assets/app.js
import './styles/app.css';
import $ from 'jquery';
import 'bootstrap';
Optimisation des performances :
Compression des fichiers
Cache busting (versioning automatique)
Chunking (découpage des fichiers)
Lazy loading
Développement plus efficace :
Hot reload (rechargement automatique)
Source maps pour le debugging
Watch mode (recompilation automatique)
Organisation des assets 
assets/
├── app.js              # Point d'entrée JavaScript
├── styles/
│   └── app.scss        # Styles SCSS
├── images/             # Images
└── controllers/        # Contrôleurs JavaScript
Intégration avec Symfony :
{# templates/base.html.twig #}
{{ encore_entry_link_tags('app') }}    {# CSS #}
{{ encore_entry_script_tags('app') }}  {# JavaScript #}

En résumé :
Modernise la gestion des assets
Améliore les performances
Facilite le développement
S'intègre parfaitement avec Symfony
C'est particulièrement utile pour les applications modernes avec beaucoup de JavaScript et CSS.



Non, le fichier webpack_encore.yaml est pour la configuration générale de Webpack Encore. Pour configurer Bootstrap, vous devez :
Installer les dépendances :

npm install bootstrap @popperjs/core --save


Créer/Modifier le fichier webpack.config.js à la racine du projet :

const Encore = require('@symfony/webpack-encore');

Encore
    .setOutputPath('public/build/')
    .setPublicPath('/build')
    .addEntry('app', './assets/app.js')
    .enableStimulusBridge('./assets/controllers.json')
    .splitEntryChunks()
    .enableSingleRuntimeChunk()
    .cleanupOutputBeforeBuild()
    .enableBuildNotifications()
    .enableSourceMaps(!Encore.isProduction())
    .enableVersioning(Encore.isProduction())
    .configureBabel((config) => {
        config.plugins.push('@babel/plugin-proposal-class-properties');
    })
;

module.exports = Encore.getWebpackConfig();

Oui, il faut laisser le terminal ouvert quand vous utilisez npm run watch. Voici pourquoi :
Mode Watch :
La commande watch surveille les changements dans vos fichiers
Recompile automatiquement quand vous modifiez un fichier
Met à jour le build en temps réel
Options de développement :
npm run watch : Garde le terminal ouvert et recompile automatiquement (développement)
npm run build : Compile une fois et s'arrête (production)
npm run dev : Compile une fois et s'arrête (développement)
Workflow typique :

# Terminal 1 - Pour Symfony
symfony serve

# Terminal 2 - Pour Webpack Encore
npm run watch

npm run dev

Avantages de watch :
Développement plus rapide
Pas besoin de recompiler manuellement
Feedback immédiat sur les erreurs
Hot reload (rechargement automatique du navigateur)
Si vous fermez le terminal, les changements dans vos assets ne seront plus compilés automatiquement.
